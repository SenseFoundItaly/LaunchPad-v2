# LaunchPad — agent guide

Next.js app (App Router) deployed to Netlify via OpenNext. Prod: launchpad.sensefound.io. Locales EN/IT.

## Architecture
- **DB**: Supabase Postgres via postgres.js. Use `query`/`run`/`get` from `@/lib/db` with `?` placeholders. IDs via `generateId('prefix')`. JSONB columns: bind the RAW object — `JSON.stringify` double-encodes.
- **LLM**: task→tier routing in `src/lib/llm/router.ts` (cheap Haiku 4.5 / balanced Sonnet 5 / premium Opus 4.7), IDs + pricing in `models.ts` — entries marked `legacy: true` are kept only so telemetry prices historical rows and never win a tier. The agent runtime is `runAgent` from `@/lib/pi-agent` (NOT `src/agents`). Chat `ARTIFACT_INSTRUCTIONS` live inline in `src/app/api/chat/route.ts` — editing `prompts.ts` is a no-op. Keep chat on Sonnet: smaller models break the artifact contract — except `chat-followup` ("yes", "go ahead" via `isSimpleFollowUp`), deliberately routed to Haiku with ZERO skill tools. That is a separate cache namespace, so the empty array is safe there and only there.
- **Prompt cache is the chat cost model.** Anthropic bills on a PREFIX match over tools → system → messages, so anything that changes per turn re-bills everything behind it. Measured before the fix: cache *writes* were 74% of chat spend. Two consequences that look like optimisations but are the opposite: (a) never drop tools from the array to "save tokens" — a stable superset rides the cache at 0.1×, a flipped array rewrites the whole prefix. The only sanctioned variation is project STATE (the prereq gates in the chat route), which changes rarely — never a per-message classifier or intent regex; (b) keep the static system half byte-identical (`CHAT_CACHE_SPLIT`, below).
- **Design**: CSS variables, no Tailwind. Primitives (`Panel`, `Pill`, …) from `@/components/design/primitives`. Layout: `div.lp-frame` → TopBar + NavRail + content. Pages are `'use client'`.
- **API**: respond with `json({success, data})` / `error(msg, status)`. Middleware returns 415 on mutating `/api` requests without `Content-Type: application/json`.
- **Cost**: `recordUsage` / `isProjectCapped`. Cron entrypoint: `GET /api/cron`.
- `@/lib/journey` (7-stage evidence checks) is NOT `@/lib/stages` (pipeline skills). Two stage pointers exist: `projects.current_step` vs journey `activeStage`.
- **i18n**: in-project UI locale comes from `project.locale` (LocaleProvider mounted in the project layout), not the account locale.

## Product invariants
- Skills **propose, not run**: `run_skill` pending_action + executor. A new `action_type` needs BOTH the TS union AND a DB CHECK migration.
- Validation gate: nothing turns green without explicit founder approval (e.g. `market_size` needs an `approved: true` stamp).
- The system must never dead-end the founder: any gating loop/review needs a dismiss/override path — **and an exit path**: a founder who has decided to stop must not be forced to finish first.
- A new gate check needs its **write path** too (keyword family → chat-sweep family → item kind → source mapping → executor Apply prefix, which must itself match the keyword family). A check reading a column nothing fills is permanently red.

## Footguns
- OpenNext 404s a static leaf after two dynamic segments (`[a]/…/[b]/verb`) — fold the verb onto the dynamic leaf.
- **Migration numbers come from `_migrations` in the live DB, never from the file tree** — the tree can't show a migration applied but never merged, which is how 037 collided. Five duplicates exist (008/009/020/037/040); a test refuses new ones.
- `schema.sql` drifts from prod — verify columns against the live DB before relying on it. `_migrations` is the only trustworthy record. **Work against prod; do not write to staging unless asked.** Staging's DB is to be rebased from prod, which gives it prod's `_migrations` and makes the runner work there normally — until that happens its schema came from `schema.sql` and has no ledger, so `db/migrate.ts` now REFUSES any populated DB with an empty ledger rather than replaying 001-0NN over it (`--i-know-the-ledger-is-empty` overrides).
- dev == prod: there is ONE Supabase project; local testing hits prod data.
- **Proposer idempotency is not one-size-fits-all.** `phase1-watchers` records a permanent marker so a rejected *suggestion* sticks. Copying that onto a **required** step bricks it (reject → never re-asked → check red forever). For required steps guard on STATE ("already decided / card already open"), never history.
- Chat option-sets have **two renderers** — `OptionSetCard.tsx` and the inline one in `chat/page.tsx`. A new option field must be handled in both or it silently no-ops in one.
- **A new model = MODEL_CONFIG + a catalog check.** pi-ai 0.84 (`@earendil-works/*`) ships current data-driven catalogs (`dist/providers/data/*.json`) — the old LP_EXTRA_MODELS shim is gone. Add the `MODEL_CONFIG` entry, then verify `getModel(provider, id)` resolves on BOTH wire paths and its catalog pricing matches yours (the cost meter must not drift); a miss throws `[pi-agent] unknown model <provider>:<id>` — grep that when a new model 500s. Thinking-off is catalog-driven now (`thinkingLevelMap.off`), so verify the entry sends OFF explicitly when reasoning is unset. NOTE: `streamSimple`/`getModel`/`getEnvApiKey` come from `@earendil-works/pi-ai/compat`, which upstream documents as temporary — budget a move to the `Models`/`createModels()` API before the next major bump.
- **`agent.state.tools` is a snapshot — mutating it mid-run does nothing.** `Agent.prompt()` copies tools once at run start and the loop reads only that copy, so the old "strip tools to force synthesis" trick was a silent no-op for months. Per-turn tool budgets belong in pi-agent-core's `beforeToolCall` hook (`makeToolCallLimiter` in `pi-agent.ts`), which blocks the call with an instructive error and keeps the tool array — and therefore the cache prefix — intact.
- **`CHAT_CACHE_SPLIT` is provider-gated, not just flag-gated.** It defaults ON but self-disables unless the active provider is OpenRouter, because only the patched `openai-completions.js` splits on the breakpoint marker and strips it. Dropping `OPENROUTER_API_KEY` therefore silently turns the cache split off too (correctly — but it is a surprising coupling). `patches/` is applied by patch-package on install; an install that skips postinstall ships an unpatched provider. On pi-ai 0.84 an unpatched provider is *less* catastrophic than before — upstream strips nothing but our patch's defensive sweep does, and native cc still applies to the whole system block — yet the split's ~50% saving silently vanishes and the sentinel WOULD leak on any path the patch misses. Two guards catch it (`scripts/deploy.sh` refuses to build, and a `cache-breakpoint.test.ts` case asserts the patch is present); keep both if you touch this. The patch pins the exact pi-ai version, so **bumping pi-ai silently un-patches** — re-cut `patches/@earendil-works+pi-ai+<ver>.patch` (target: `dist/api/openai-completions.js`, functions `addCacheControlToInstructionMessage` + the post-`applyAnthropicCacheControl` strip) on every bump.

## Build / test / deploy
- Worktrees have no own `node_modules` (symlinked from the main checkout): use `node_modules/.bin/tsc` (npx false-passes) and `next build --webpack` / `next dev --webpack` (turbopack panics on the symlink).
- Tests: `vitest`; live e2e sims are `node scripts/e2e-*.mjs` / `sim-*.mjs`. Auth bypass for QA: `E2E_AUTH_ENABLED=1` + `x-e2e-user` cookie/header — honoured ONLY when `CONTEXT` says this is not a deployed site (`e2e-bypass.ts`). The flag alone used to be the guard and staging served it publicly; setting it on a deploy now does nothing.
- Deploy: `npm run deploy` (netlify-cli upload, NOT git CI) from the real main checkout only. To clear cache remove ONLY `.netlify/functions-internal` and `.next` — never `.netlify` itself (deletes the project link).
